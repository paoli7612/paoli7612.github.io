Capitoletto 2.5

Protocolli e servizi applicativi

Al livello applicativo troviamo i servizi visibili agli utenti e ai programmi: pagine web, nomi di dominio, posta, configurazione automatica e trasferimento file.

HTTP e HTTPS

HTTP è il protocollo usato dal Web per richiedere risorse come pagine HTML, immagini, fogli di stile e dati JSON. HTTPS aggiunge cifratura e autenticazione tramite TLS, proteggendo il traffico tra client e server.

GET /index.html HTTP/1.1
Host: esempio.it

Il server risponde con un codice di stato, intestazioni e contenuto della risorsa richiesta.

DNS e DHCP

DNS traduce nomi leggibili, come www.scuola.it, in indirizzi IP. DHCP assegna automaticamente parametri di rete ai client, come indirizzo IP, subnet mask, gateway e server DNS.

Posta e trasferimento file

SMTP invia messaggi di posta tra client e server o tra server. IMAP permette di consultare la casella mantenendo i messaggi sul server. Per il trasferimento file si incontrano FTP, SFTP e servizi basati su HTTP.

Studiare i protocolli applicativi significa osservare sia il servizio offerto sia i livelli inferiori che lo rendono possibile.

Diagnostica ragionata

Quando un servizio non funziona conviene procedere per livelli: collegamento attivo, indirizzo IP corretto, gateway raggiungibile, DNS funzionante, porta aperta, server applicativo configurato.

Metodo

Prima verifica l'indirizzo IP locale, poi il gateway, poi un indirizzo esterno, poi il nome DNS e infine il servizio specifico.

Ripasso

Perché DNS è fondamentale per il Web?

Perché gli utenti usano nomi, ma la rete instrada pacchetti verso indirizzi IP.

Qual è la differenza essenziale tra HTTP e HTTPS?

HTTPS usa TLS per cifrare la comunicazione e verificare l'identità del server.
